# 证据规则 / Evidence Rules

> **本 skill 的公信力全部来自这一份文件。**
> 一旦开始把推测写成事实，整份规划就变成算命——只是换了个包装。

---

## 一、四级证据链

| 等级 | 定义 | 来源举例 | 允许的表述 |
|---|---|---|---|
| **L1 事实** | 可被第三方验证的客观记录 | 银行流水、工资条、病历、体检报告、代码提交记录、文件数量与时间戳、合同、发票 | 「你的月现金流是 X」（直接陈述） |
| **L2 自述** | 用户的主观陈述，未经外部验证 | "我情商不够"、"我不擅长社交"、"我三分钟热度" | 「你自述 X」（必须标明归属） |
| **L3 假设** | AI 基于材料的推断 | "你的问题可能是机制错配" | 「我的假设是 X，你可以推翻」（必须可被推翻） |
| **L4 已验证** | 假设经过追问或外部证据确认 | 假设「缺乏持续力」被 3 年日记推翻 | 「这一点验证过：X」 |

**铁律**：**禁止把 L3 写成 L1，也禁止把 L2 当 L1。**

### 1.2 四段式：事实 → 解释 → 假设 → 验证

用户说的话里，**事实和解释是混在一起的**。拆不开，整个审计就建立在解释之上。

```
用户说：「我这人就是懒，做什么都坚持不下来。」
```

| 段 | 动作 | 本例 |
|---|---|---|
| **① 事实** | 问出可验证的具体行为 | 「具体是哪件事没坚持？多久？当时发生了什么？」→ 事实是「过去 18 个月有 5 个副业项目，平均存活 6 周」 |
| **② 解释** | 认出这是他的归因，不是事实 | 「懒」是他的解释，不是观察 |
| **③ 假设** | 提出竞争性解释 | 「可能不是懒，是这 5 个项目都没有在 6 周内产生外部反馈」 |
| **④ 验证** | 找一个能区分两个解释的证据 | 「有没有哪件事你做了超过 6 个月？那件事有什么不同？」→ 若有客户/有反馈，假设成立 |

**只有走完第 ④ 步，才允许写进报告。** 停在 ③ 就是算命。

### 1.3 置信度三档

报告头部和关键结论必须标：

| 档位 | 判定标准 | 表述 |
|---|---|---|
| **高** | 有多条 L1 支撑，且无反向证据 | 「基本可以确定」 |
| **中** | 有 L1 但样本少，或主要靠 L2 + 逻辑 | 「我倾向这个判断，但样本只有 N」 |
| **低 / 待验证** | 主要是 L3，或数据缺失 | 「这是假设，需要 X 来验证」 |

**分布要求**：一份诚实的高质量报告，通常是「高 40%、中 40%、低 20%」。全是高置信度，就是不诚实。

### 1.4 假设-建议联动（必写）

**每一个重要建议，都必须挂一个「如果假设错了，建议怎么改」。**

| 假设 | 置信度 | 若假设不成立，建议改为 |
|---|---|---|
| 行业 3 年内不会回暖 | 中 | 改为「2 年内在行业内换到有客户资产的位置」，而非转行 |
| 每周可稳定投入 10 小时 | 中 | 若实际只有 4 小时，路线图整体拉长 2.5 倍，优先做现金而非能力建设 |
| 副业能在 12 个月内覆盖 50% 工资 | 低 | 若 6 个月无付费客户，停止投入，改为「换岗」路径 |

**这张表是报告可信度的核心。** 它承认了「我可能错」，并且给出了错的应对方式。

## 二、禁止句式清单

以下句式一律不许出现在输出里：

| 禁止 | 为什么 | 改成 |
|---|---|---|
| 「你是 XX 型的人」 | 人格标签不可证伪，且会自我固化 | 「你在 X 场景下表现出 Y，在 Z 场景下不同」 |
| 「你天生就 XX」 | 归因到不可改变的因素 | 「你目前在这些条件下会 XX」 |
| 「你的命里 XX」 | 宿命论，直接封死改变的可能 | 转入七步校验 |
| 「你适合做 XX」 | 无法验证，也无法执行 | 「在 A 条件下你能做成，在 B 条件下会断」 |
| 「大部分人都会 XX」 | 用群体概率替代个体判断 | 「基础概率大约是 X%，你的情况是否吻合需要看 Y」 |
| 「只要坚持就一定能 XX」 | 空头承诺 | 「如果每周做 X，一年后可能出现 Y，但不是保证」 |
| 「你应该 XX」 | 替用户做决定 | 「如果你选 A，代价是 X；选 B，代价是 Y」 |

## 三、结论表述模板

### 3.1 陈述事实（L1）

```
【事实】截至 {时间}，{指标} 为 {数值}（来源：{出处}）。
```

### 3.2 转述自述（L2）

```
【你的说法】你提到"{原话}"，我按这个理解。
```

### 3.3 给出推测（L3）

```
【我的推测】{结论}。
依据是：{证据1}、{证据2}。
这个推测可能是错的，如果 {反例情况} 成立，它就站不住。
```

### 3.4 处理矛盾

当 L1 和 L2 冲突时（用户说"我存不下钱"，但流水显示每月结余 3000）：

```
【这里有个矛盾】你说 {自述}，但记录显示 {事实}。
两种可能：① 记录不完整 ② 你的感受和实际不一致。
你倾向哪一种？
```

**不许单方面采信任何一方，也不许忽略矛盾。**

## 四、不确定性的正确表达

**不要用"可能""也许""大概"这种含糊词，要用明确的不确定性来源。**

| 差 | 好 |
|---|---|
| 「你可能会成功」 | 「如果 X 成立，成功率较高；如果 Y 成立，概率很低」 |
| 「这个方向应该不错」 | 「这个方向在 {条件} 下成立，我目前没有 {某项数据}，所以判断置信度中等」 |
| 「大概需要一年」 | 「按每周 10 小时投入估算，需要 9–14 个月，取决于 {关键变量}」 |

---

## 五、数字的纪律

1. **所有金额必须给区间，不给单点**：不说"能撑 35 个月"，说"35 个月（保守 30，乐观 40）"
2. **所有时间估算必须给依据**：不说"三个月能做完"，说"按你每周 10 小时、这类项目通常 60–80 小时估算"
3. **所有比例必须给分母**：不说"命中率 40%"，说"15 条预测中 6 条命中，9 条未中或无法判定"
4. **算错要认**：发现计算错误时，明确说"上一轮我算错了，正确是 X"，不悄悄改

## 六、自我校验清单

输出前逐条过一遍：

- [ ] 每一个数字都有来源或计算过程？
- [ ] 每一句判断都标注了 L1/L2/L3/L4？
- [ ] 有没有出现禁止句式？
- [ ] 有没有把用户的自我评价直接当成事实？
- [ ] 有没有替用户做决定？
- [ ] 有没有给出"不可证伪"的结论？
- [ ] 矛盾之处是否被指出，而不是被抹平？
- [ ] 关键判断是否走完了「事实→解释→假设→验证」四段？
- [ ] 每条重要建议是否挂了「若假设不成立，建议改为」？
- [ ] 置信度分布是否诚实（不是全高）？
